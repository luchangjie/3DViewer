# 3DViewer 架构说明

本文档说明 3DViewer 的整体设计：构建链、渲染管线、BVH 加速、体素化与光照。

## 1. 总览

程序分为两部分，通过 DLL 解耦：

- **主程序（Win32，`src/main.cpp` + `3DViewer.vcxproj`）**：负责窗口、消息循环、鼠标 / 键盘交互、OBJ / 体素加载、CPU 端 BVH 构建，并**运行时动态加载** `render_kernel.dll`（`LoadLibraryA` + `GetProcAddress`），取出 5 个导出函数：
  - `cudaInit`：初始化 CUDA、分配帧缓冲 / 深度缓冲 / 分块缓冲
  - `cudaUploadTriangles`：上传三角形到 GPU
  - `cudaUploadBVH`：上传 BVH 节点到 GPU
  - `cudaRender`：渲染一帧（清屏 → 预处理 → 分块 → 光栅化 → 拷回主机）
  - `cudaShutdown`：释放 GPU 资源
- **渲染内核（`src/render.cu` + `render_kernel.vcxproj`，NVCC 编译为 DLL）**：在 GPU 上做逐像素光栅化，结果以 BGRA 帧缓冲返回，再由 **Direct2D**（`Direct2DDisplay.h`）贴到窗口。

公共数学（`Vec3` / `Mat4`）和结构体（`GPUTriangle` / `RenderParams` / `BVHNode` 等）放在 `src/render.h`。该文件用宏在非 CUDA 编译时也定义 `__host__/__device__`，因此 CPU 侧代码能直接复用这些类型。

## 2. 构建链

```
cl  (src/*.cpp  → 主程序 obj)        NVCC (src/render.cu → render_kernel.dll)
        │                                      │
        └────────── link ──────────┬──────────┘
                           3DViewer.exe + render_kernel.dll
```

- `render_kernel.vcxproj`：CUDA 工程，产出 `render_kernel.dll`。
- `3DViewer.vcxproj`：主程序工程，产出 `3DViewer.exe`，运行时链接 DLL 的导入库。
- 两个文件必须同目录，否则 `LoadLibraryA("render_kernel.dll")` 失败。

## 3. 渲染管线（`cudaRender`，每帧）

1. **清屏 `clearKernel`**：垂直渐变背景，深度缓冲置 `FLT_MAX`。
2. **三角形预处理 `computeTriCacheKernel`（每三角形一线程）**：
   - 用 MVP 计算裁剪空间坐标；
   - 近裁剪面裁剪（Sutherland-Hodgman，最多把 1 个三角切成 2 个）；
   - 预算基础颜色（环境光 + 主光漫反射 + 补光 + 半球环境光）；
   - 计算屏幕像素包围盒；
   - 裁剪后三角写入 `ClippedTri` 缓冲。
3. **分块构建 `buildTileKernel`（每 16×16 像素块一线程）**：
   - 若已上传 BVH，走**显式栈的 BVH 遍历**，用节点屏幕包围盒做视锥 / 块相交剔除；
   - 否则暴力遍历所有三角形；
   - 每个块记录“覆盖本块的三角形索引”。
4. **光栅化 `rasterizeKernel`（每像素一线程）**：遍历所在块的三角形 → 重心坐标 → 深度测试 → Blinn-Phong 高光 → 线框模式判断 → 写 BGRA。
5. **`cudaMemcpy`** 把设备帧缓冲拷回主机内存，交给 Direct2D 显示。

## 4. BVH 加速

- **构建**：`bvh_builder.cpp` 在 CPU 端完成。对每个三角形算 AABB 与中心，递归按最长轴中位数分割（`std::nth_element`），叶子最多 8 个三角形。构建后会**按 BVH 顺序重排三角形**。
- **使用**：节点是模型空间 AABB；每帧在 `nodeScreenBounds` 中用 MVP 把节点 8 个角点投影到屏幕，得到保守包围盒，再与每个 tile 求交剪枝。只对可能覆盖某块的节点 / 三角形做后续处理。
- 注意：即使 BVH 未上传，管线也能回退到暴力遍历，不会崩。

## 5. 体素化（`voxel_loader.cpp`）

- 先按 OBJ 载入三角面，求整体包围盒，按 `g_voxelResolution`（默认 64，可调 64–1280）划分体素网格。
- 用**粗网格**（`GRID_RES`）做三角形–格子预分配，加速后续查询。
- 对每个体素中心做**三角–体素相交检测**：先 AABB 粗筛，再用 **SAT（分离轴定理，9 条边轴 + 1 个面法轴）** 精确判断，OpenMP 并行。
- 命中体素写入位图（`VoxelBitmap`，每字节存 8 个体素，省内存）。
- 生成表面：只给“某个面相邻的体素为空”的面补立方体三角面，按法线主方向给灰阶（X/Y/Z 不同灰度），最后整体归一化到 `[-1,1]` 方便查看。
- 导出：`exportVoxelObj` 用哈希去重顶点，写出带法线的 OBJ。

## 6. 光照

最终颜色 = 预算基础色（环境 + 漫反射 + 补光 + 半球项）+ Blinn-Phong 高光。

- 高光在 `rasterizeKernel` 中用 `modelView` 把法线转到视图空间，正确响应模型旋转。
- **漫反射坐标系（已修复）**：原先 `computeTriCacheKernel` 用模型空间法线点乘视图空间光向（`render.cu` 约 216–237 行），旋转模型时漫反射不变。现已用 `modelView.mulDir(N)` 把法线转到视图空间再点乘，漫反射会随模型旋转正确变化。
